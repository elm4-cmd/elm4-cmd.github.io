1. Översikt

Den här policyn gäller Android-appen Röd Puls: Följ Luleå Hockey (”Röd Puls”), publicerad av elm_cr4. Röd Puls samlar matchinformation, nyheter, statistik, supporterprofiler och forumfunktioner på ett ställe.

Appen använder uppgifter för att tillhandahålla valda funktioner, autentisera konton, visa offentligt profil- och foruminnehåll, spara inställningar samt skydda tjänsten mot fel och missbruk. Uppgifter säljs inte till annonsörer.

2. Gästläge, konton och inloggning

Röd Puls kan användas som gäst utan ett appkonto. Gäster kan läsa sådant innehåll som gjorts offentligt tillgängligt men kan inte skriva i forumet, gilla eller följa trådar.

Om du väljer att skapa ett konto kan du använda e-postadress och lösenord eller Google-inloggning. Firebase Authentication behandlar autentiseringsuppgifter, e-postadress, ett unikt Firebase UID, inloggningsleverantör och information som behövs för att upprätta och skydda sessionen. Vid Google-inloggning behandlar Google och Firebase relevanta Google-identitetsuppgifter, exempelvis Google-kontoidentifierare och tillgänglig grundläggande profilinformation.

Lösenord hanteras av Firebase Authentication. Röd Puls lagrar inte lösenord i appens profil- eller forumdatabas. Läs mer om Firebase Authentication och användaruppgifter i Firebase Authentication.

3. Användarprofiler, forum och synlighet

Cloud Firestore används för användarprofiler och forum. Beroende på hur du använder appen kan följande uppgifter lagras:

  • valt användarnamn, bio och avatarval;
  • trådar, kommentarer och svar som du publicerar;
  • likes och summerade like-antal;
  • följda trådar och summerade kommentarsantal; och
  • tekniska tidsstämplar och interna referenser som behövs för funktionerna.

Användarnamn, bio, trådar, kommentarer och svar kan vara offentligt synliga även för personer som inte är inloggade. Forumdokument innehåller även ett tekniskt Firebase UID för att koppla innehåll till rätt profil. UID:t visas inte som ett vanligt profilfält i appens gränssnitt, men ingår i den tekniska forumstrukturen.

Enskilda like-poster och listan över följda trådar är privata och kan inte listas offentligt. Summerade antal likes och kommentarer visas däremot som en del av det offentliga foruminnehållet.

Lägg inte känsliga personuppgifter i användarnamn, bio, trådar, kommentarer eller svar. Publicera bara information som du är bekväm med att andra kan läsa.

4. Teknisk data för drift och säkerhet

Firebase och Google kan behandla IP-adress, user-agent samt teknisk information om enheten, appen, operativsystemet och nätverksbegäran. Informationen används bland annat för drift, autentisering, säkerhet, felsökning och skydd mot missbruk.

Firebase Authentication kan använda IP-adress och user-agent för kontosäkerhet. Cloud Functions kan tillfälligt behandla IP-adresser när serverfunktioner körs. Vissa tjänstenivå- och säkerhetsloggar som behandlas av Google eller Firebase omfattas av leverantörernas egna säkerhets-, rättsliga och lagringsregler. En kontoradering i Röd Puls innebär därför inte ett löfte om omedelbar radering av alla sådana leverantörsloggar.

Mer information finns på sidan Privacy and Security in Firebase och i Googles integritetspolicy.

5. Lokal lagring, offline-cache och Android-backup

Android DataStore används lokalt för inställningar och viss appdata, exempelvis introduktionsstatus, valda inställningar, lästa eller sparade objekt och lokala profilval.

Om du väljer att importera egna profil- eller lagbilder lagras dessa endast lokalt i appens privata lagringsutrymme. De laddas inte upp till Röd Puls backend.

Cloud Firestore kan använda en lokal offline-cache för att göra tidigare hämtat innehåll tillgängligt och förbättra appens funktion vid tillfälliga nätverksproblem. Lokal appdata kan, beroende på Android-version samt dina enhets- och backupinställningar, omfattas av Androids systembackup. Att rensa appdata eller avinstallera appen påverkar lokal data enligt Androids funktioner, men raderar inte i sig ett Röd Puls-konto i Firebase.

6. Tjänsteleverantörer och säker överföring

Röd Puls använder Google Firebase som teknisk tjänsteleverantör:

  • Firebase Authentication för konton och inloggning;
  • Cloud Firestore för profiler, forum och relaterad funktionalitet; och
  • Cloud Functions for Firebase för säker serverbehandling, inklusive fullständig kontoradering.

Data skickas krypterat till Firebase och Google via HTTPS/TLS. Åtkomst till Firestore-data styrs genom autentisering och säkerhetsregler. Google behandlar data enligt tillämpliga avtal och sin egen integritetspolicy när företaget tillhandahåller tjänsterna.

7. Externa nyhetslänkar

Röd Puls kan visa länkar till nyheter eller andra externa webbplatser. När du öppnar en sådan länk lämnar du appen och sidan öppnas i din webbläsare. Den externa webbplatsens ägare ansvarar för sin egen databehandling, sina cookies och sin integritetspolicy.

Den här juridiska webbplatsen innehåller inga analys- eller spårningsscript och sätter inga egna cookies. Den använder inga externa typsnitt. Webbplatsen tillhandahålls via GitHub Pages, och GitHub kan behandla vanliga webb- och säkerhetsloggar enligt sina egna villkor och sin integritetspolicy.

8. Annonsering och telemetri som inte används

Den aktuella releasen av Röd Puls använder inte annonser och samlar inte in Advertising ID. Den använder inte Firebase Analytics, Firebase Crashlytics eller någon annan extern användartelemetri för analys, marknadsföring eller kraschrapportering.

9. Lagring samt konto- och dataradering

Kontouppgifter och användarskapat innehåll lagras så länge kontot och innehållet behövs för att tillhandahålla de funktioner du använder, eller tills du begär radering.

Du kan radera kontot i appen via Hantera konto → Radera konto. Du kan behöva autentisera dig igen innan raderingen genomförs. Om du inte längre har appen kan du följa instruktionerna på sidan Radera konto och data.

Vid en fullständig kontoradering tas Firebase Authentication-kontot och appdata som kan kopplas till Firebase UID:t bort. Det omfattar profil, username-reservation, användarens trådar, kommentarer, svar, likes, följda trådar och relevanta UID-kopplade referenser.

Efter slutförd radering kan en minimal säkerhetsmarkör kopplad till Firebase UID:t behållas i högst 24 timmar för att blockera redan utfärdade autentiseringstoken. Markören innehåller ingen profil- eller forumdata och tas därefter bort.

Om en radering avbryts på grund av ett tekniskt fel markeras den inte som slutförd. Ett tekniskt lås kan då ligga kvar för att förhindra ny kontodata tills raderingen kan återupptas säkert.

11. Ändringar i policyn

Policyn kan uppdateras när appens funktioner, tjänsteleverantörer eller rättsliga krav förändras. Den aktuella versionen och datumet för senaste uppdatering publiceras på den här sidan.
